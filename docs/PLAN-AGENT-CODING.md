# agent 模式二版：照 coding agent 的样子重做

2026-09-22。前身是 [PLAN-AGENT-MODE.md](PLAN-AGENT-MODE.md)（一版设计）与 [AGENT-MODE-STATUS.md](AGENT-MODE-STATUS.md)（一版落地后的现状与差距）。本文是二版的计划，取代一版 §五的形状；一版 §一的用户定案（不替代扮演、只有一个输入框、对话不进正文、账本走旁路）全部保留。

## 一、参照物（用户 2026-09-22 定，不得改写）

> agent 模式下我们的参照对象就应该是现在的你和我：我和你在讨论，你有结论后去改文件代码；你能够精准匹配文件、匹配里面的每一行；能够检索到所有相关文件；每一次改动都有记录；还能用 git 保存在本地，能够随意读取 git 覆盖。agent 模式下我们应该尽可能靠近 coding agent。

同日补定：**不直接用 git，只要 git 的原理**——数据保存在本地、随时保存、随时覆盖回去。**会话树导航是扮演用的，agent 模式废弃。**

逐项翻译成梨园里的东西：

| 参照物 | 二版 | 一版（要退场的） |
|---|---|---|
| 项目就是磁盘上的一个目录，路径稳定 | `正文/` 目录本身就是稿子；一章一个 `.md` 文件；文件名即顺序与标题 | 版本堆 `<id>.v<n>.md`，稿子＝会话树的投影 |
| `Read` 带行号精确到行、`Grep` 检索全部文件、`Edit` 匹配原文改、一轮改多个文件 | 原生 read / grep / find / ls / edit / write 直接对着章文件 | `story_read`（UTF-16 偏移）、`story_grep`、`story_edit`（单章、版本锁） |
| 每次改动有记录、本地保存、随意恢复覆盖 | 子项目里的**快照仓**：每轮一个检查点，历史是一条线，任一检查点可恢复 | 会话树条目、树导航、世界线 |
| 工具回执用完可压缩，文件是真相 | 讨论历史认 pi 的 `compaction`，正文不靠历史保真 | 所有回执永久回放，无压缩 |
| 我读多少自己判断 | 项目状态块只带数据（账本、名录、前情、稿子目录）；正文读不读归模型 | 硬带 6000 字尾部 |

## 三、磁盘形状

```
cards/<卡>/对话/<子项目>/
  对话.json            mode: "agent"
  会话/                pi sessionDir：讨论、rp-state、rp-summary、liyuan-process、沙箱授权
  正文/                ← 稿子。就是这些文件，没有别的
    001-初雪.md
    002-长街.md
  历史/                ← 快照仓（第四节）
    对象/<sha256>      内容寻址的文件快照，只增不改
    检查点.jsonl       一行一个检查点
  世界状态.json  面板.json  向量记忆/
```

- **一章一文件**。文件名由模型（或用户）起，harness 只定一条数据规则：`正文/` 下按文件名字典序排列的 `.md` 文件序列＝稿子；不读子目录；不认 frontmatter。给模型的一句事实（写在 `AGENT.md`，不是催告）：文件名决定顺序，建议 `NNN-标题.md`。改标题＝改名，插章＝起一个落在中间的名字。
- **`正文/` 完全开放给原生读写**。`历史/` 与 `会话/` 属 harness 管理，原生写 deny（保留 `harnessManagedPath` 的形状，对象换掉）。
- **删掉一版的**：`rp-chapter` / `rp-chapter-revision` 条目、`projectChapters`、`StoryStore`、`chapterFileName`、`newChapterId`、`.v<n>` 命名、`世界线.json` 在 agent 子项目里的使用。已有的 agent 子项目只在本机（三刀未 push、未发版），不写迁移；开发机上那几个直接删。

## 四、快照仓：git 的原理，没有 git

### 4.1 数据

- **对象**：`历史/对象/<sha256>`，文件内容按哈希存一份，同内容不重存。这就是 git 的 blob。
- **检查点**：`历史/检查点.jsonl` 每行一条：

  ```
  { id, ts, author: "agent" | "user", turnId?, message, files: { "001-初雪.md": "<sha>", … }, changed: { added, modified, renamed, removed } }
  ```

  `files` 是这一刻 `正文/` 的完整清单（git 的 tree），`changed` 是与上一条的差（展示用，可由 `files` 重算）。`turnId`＝这轮 user 条目的 id，是讨论与文件之间唯一的对应关系。
- **只增不改**：对象与检查点都是追加；恢复到旧检查点之后再改，产生的是新检查点，旧的仍在。这是 git reflog 的性质，比 git 更简单：一条线，没有分支指针。

### 4.2 什么时候落检查点

- **讨论轮结束**（`finishAuthoring` 之后）：`正文/` 与上一检查点清单不同 → 落一条，`author: "agent"`，`message`＝本轮用户原话前 60 字，`turnId`＝本轮 user 条目。工作树没变（纯讨论）→ 什么都不落。
- **用户直接改稿**（稿子视图编辑 → `POST /api/story/edit` → 写文件）→ 立即落一条，`author: "user"`，无 `turnId`。
- **用户中途停止**：文件已改的部分照样落检查点（`message` 标 `已中止`）——改了就是改了，不回滚。
- 模型没有「保存」工具。它像 Claude Code 一样只改文件；保存是 harness 的事。

### 4.3 恢复：两种，形态照 Claude Code 的 rewind

历史视图列出全部检查点（时间、作者、message、改了哪些文件）。选一条，两个动作：

1. **只恢复文件**：把 `正文/` 重写成该检查点的清单（多出来的文件删掉、缺的从对象仓写回）。讨论不动——模型下一轮读文件就知道内容变了，跟我在 Claude Code 里 `git checkout` 一样。落一条新检查点 `message: 恢复到 <id>`。
2. **文件和对话一起恢复**：文件同上，讨论截到该检查点的 `turnId` 那条 user **之前**（即那次输入还没发出的状态，输入框可预填原话）。这是「回到某一次输入」。底层挪 pi 叶子仍走 `navigateTree`（pi 唯一移动叶子的通道），但它是实现细节——**agent 模式不提供树导航、世界线、`/rewind`、`/reroll`、`/drop`、「回退到此章之后」**，这些都是扮演的机制。被截掉的讨论在 pi 的树上仍存在，agent 模式不提供导航回去的入口；要「回到未来」就再恢复到更晚的检查点（文件回来，讨论不回来——讨论层不是真相，接受）。

无 `turnId` 的检查点（用户手改）只有动作 1。

### 4.4 不做

- 分支、合并、远端、标签。
- 给模型任何历史工具；它要看改动史，历史在用户面前的视图里，不在它的上下文里。
- 检查点上的检查器（字数、格式）。

## 五、工具

- 原生 `read` 带行号、`grep` 带文件与行、`edit` 唯一原文匹配、`write` 整文件——pi 已经发行的协议，梨园不再包一层。
- **不上清单**：`worldline_*`（世界线＝树分支，agent 无树）、`story_*`（删）、稿纸 / 上一拍 / `beat_plan` / `conversation_mode`（一版已不给）。
- 沙箱：cwd 仍是卡目录，卡外照旧问用户；`历史/`、`会话/` 对原生写 deny。
- 删掉的代码：`src/stage/story.ts` 整个模块及其在 engine / server / wire / web 的接线（`story_preview`、`story_rewind` 帧，`replaceChapterText`，`chapterRewindTarget`），扩展里 `/rewind` 对 agent 子项目的分支。

## 六、上下文：四条通道不变，两条内容变

一版 §5.4 声明的四条通道（system / 项目状态块 / 讨论历史 / 本轮回执）保持闭合，不加第五条。变的是：

1. **system**：`assets/AGENT.md` 重写，只会变短——「稿子」一节从五个工具的说明改成一句事实：正文是 `正文/` 下按文件名排序的 `.md` 文件，用文件工具读写，保存与历史由梨园管理。其余（用户规矩、卡 `AGENTS.md`、两行事实）不动。
2. **项目状态块**：前情提要、世界状态、登场名录不动；**稿子尾部换成稿子目录**——文件名、字数、最后一次改动时间，一行一个。正文不带；读不读归模型，与 Claude Code 不预读文件同形。`agentStoryTailChars` 删除。
3. **讨论历史**：`authoringHistory` 认 pi 的 `compaction` 条目（现在不认——从 `getBranch()` 全量回放）。分支上有 `compaction` 时从它的 `firstKeptEntryId` 起回放，摘要作一条 user 消息置前。这样 pi 自带的阈值压缩（`packages/coding-agent/src/core/compaction`，按模型上下文窗口比例）在 agent 轮真正生效。梨园不写第二套讨论压缩。
4. **本轮回执**：不变。

一版最大的暗伤（`write` 参数里的整章、`read` 回执里的整章永久留在历史）由第 3 条解决：压缩到期时它们被摘要掉。到期之前的重复是 coding agent 同样承受的代价，不另做剪枝器。

## 七、旁路链：挂在检查点上

轮末落检查点之后，按 `changed` 跑：

1. **场记**：只对**新增**的 `.md` 文件跑，一文件一遍，`assistantText`＝文件全文，`userText` 空——与一版相同。修改与改名不触发（改中间章后账本 / 摘要 / 后文不自动跟随，留白不变）。
2. **前情压缩**（`rp-summary`）：单位＝文件。到期判据回到字数：**未被摘要覆盖、且按文件名序排在最后 N 个文件之外**的正文 ≥ 地板字数才压。一版「每章一次」的取舍推翻——它每章多一次 4096 输出的旁路调用，而上下文里根本没有正文。N 复用 `compactEveryNTurns`（语义＝保留最近 N 个文件），地板用既有 `MIN_COMPACT_CHARS`。摘要条目记「覆盖到哪个文件」，不再记树条目 id。
3. **向量记忆**：宿主 `onTurnEnd` 对新增文件逐个入库，不变。
4. **钉档** `storeSave`：不在 agent 模式里（世界线已撤）。

恢复到旧检查点时账本不自动回滚。「文件和对话一起恢复」时讨论截到那条 user 之前，树上其后的 `rp-state` / `rp-summary` 也在截掉的范围里，账本自然对齐；「只恢复文件」时账本留在原处——两套坐标，写进文档，不做协调器。
