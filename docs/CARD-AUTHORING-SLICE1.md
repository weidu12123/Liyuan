## 使用入口

角色卡详情 → **代码与资源** → 建立创作稿。选择资源后可以查看、编辑和保存源码；「检查」「预览」会先保存当前编辑。「应用到角色卡」使用最近一次检查的版本，应用后重载；「撤回应用」还原最近一次应用前的原卡，编辑源文件保留为待修改稿。标准 JSON/PNG 导出仍使用角色卡详情的原有入口，导出的是已应用内容。

共享 `card_project` 已接入主会话写卡模式，助手侧也保留该工具；与面板调用同一份服务：

| 操作 | 内容 |
|---|---|
| `inspect` / `prepare` | 获取资源清单 / 首次展开工程；重复展开保留已有稿件 |
| `read` | 按资源 ID 读取完整原文，支持行分页；`raw` 查看只读原包 JSON |
| `write` | 按读取时的资源 hash 保存完整文本 |
| `check` | 组装变更并返回 buildHash、变更资源与语法错误 |
| `apply` / `undo` | 按 buildHash 回写并重载 / 撤回最后一次应用 |

原生文件工具也可以直接修改展开后的源文件。预览目前由面板启动；没有另起写卡 agent、自动审稿模型或模型循环。

## 资源与数据保留

共享服务是 `src/card-authoring.ts`；浏览器共用类型单独放在 `src/card-authoring-types.ts`，避免把文件系统模块打进前端。

- 卡空间工程位于 `cards/<目录>/创作/`。旧布局或外部卡使用工作区 `.liyuan-artifacts/card-authoring/<路径摘要>/`。
- `snapshots/<sha256>.card` 保存原始 JSON/PNG 字节。`manifest.json` 记录初始版本、当前应用基线和上一应用版本，快照读写均核对摘要。
- `sources/` 保存可编辑字符串。资源 ID 由**类型与原始 JSON 路径**生成，同名、同内容甚至重复作者 ID 的资源各自保留。映射每次由当前快照确定，不按作者标题推测用途。
- 当前展开卡文字字段、默认及备选开场、内嵌世界书正文、作者正则的匹配/替换字符串，以及两个历史命名空间下的助手脚本正文。
- 原卡其他数据留在快照，只回写资源所对应的字符串槽位。保存创作稿不会修改原卡。无变更应用不重写原文件；有变更时 JSON 会重新序列化，保证未修改数据的语义，不承诺整包字节不变。撤回还原原字节。
- 资源版本、构建版本、原卡基线冲突均拒绝覆盖。资源缺失和越出工程目录的符号链接会报错。源文件及卡文件使用同目录临时文件替换，应用/撤回的清单写入失败会还原卡文件。

公开导出同时修正了世界书保留逻辑：`embedded` 保留原书；`active` 保留书级信息、原条目身份及扩展，并附加活跃书条目。沿用内容去重时，活跃修改覆盖对应原条目，同 UID 优先；其余原始重复项仍保留。用户停用清单在导出时生效。没有变化的对象式 entries 保留原键，没有书的卡不添加空书。独立书的公开字段在需要时转换为卡内格式，插件扩展保留。

脚本重载从「来源＋ID＋长度」改为共用内容摘要；等长改码也会重新取得脚本并卸载旧宿主。前端忽略已经过期的脚本请求回包。

## 预览及状态归属

预览复用正式的宏、显示正则、HTML 分块、消息帧文档和 ScriptHost 文档。初始测试变量读取卡内初值或当前能够提取的 schema 默认值，也可手填测试消息与 JSON 变量。

外层 iframe 使用 `data:` 的独立 opaque origin。内层 srcdoc 可以访问预览壳，便于页面级脚本挂载组件，不能同源访问正式应用。**不能把外层改成带 allow-same-origin 的 srcdoc**，否则会失去这个边界。CSP 禁止 connect/form 请求；生成与命令桥只记录预览事件，UI 状态留在预览内。脚本/CDN 加载与实际 API 兼容性仍受环境限制，错误在面板反馈。

正式页原有的 postMessage 命令接收和 MVU 广播也收窄到由 `HtmlFrame`、`ScriptHost` 声明的正式帧；预览不能借旧消息桥发送剧情命令，或通过启动握手取得正式变量。正式组件原有的命令与变量通道仍有效。高度与宿主启动消息同时核对来源。

剧情事实仍由 agent/场记提交，组件负责搜索、折叠等 UI 状态及提交用户操作。对照 `PLAN-ROUND-FLOW.md`，此切片补的是作者把交互落实到可运行作品的能力，没有改变演员的分段选择、稿纸流程或场记记账，也没有新增提示词注入通道。卡内 `AGENTS.md` 继续是演出档案，不当作 coding agent 的开发指令。

## 当前边界与后续

1. 当前只编辑已存在的字符串资源。新增/删除资源、脚本/正则元数据与完整 manifest 编辑、源码和产物分离、外部依赖与素材携带尚未实现。
2. 检查只覆盖修改过的 JavaScript 与正则语法、卡基本结构和源文件读取；HTML 内脚本依赖运行预览发现错误。它不执行作者后台代码，不做完整 Zod/MVU 一致性校验，也不编译 TypeScript/Vue。
3. 预览遵循梨园现有宿主语义，尚未补齐 EJS、逐消息历史变量和完整 TavernHelper API。能保存模板、显示组件或通过语法检查不能代表完整生态兼容。
4. 原卡由其他入口改动后，工程会保留稿件并阻止覆盖。尚无自动三方合并或一键重新同步；需要备份旧稿、核对原卡变化后重新建立工程并迁移所需修改。没有用静默重置来掩盖冲突。
5. 写卡技能包的索引、按需资料加载和梨园接口类型/模板尚未接入；卡档案与标准卡导出的双向映射也未改变。
