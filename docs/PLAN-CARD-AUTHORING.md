# 角色卡制作与修改：独立能力维度

2026-09-07 用户补充；2026-09-08 重新定序并**点名调查中心：不只是文字内容，更重要的是代码——很多角色卡背后是有代码的**。此项位于 当前计划 的**第二步**。两种工具调查及 [资源编辑第一切片](CARD-AUTHORING-SLICE1.md) 已完成。2026-09-09 按用户进一步定案，落地主会话 写卡模式：同一份底层记录按模式开放操作内容，支持扮演中实时维护，回去续演时重新封闭维护过程。用户随后决定转入**实际体验与反馈调整**，后续补齐范围由具体使用需求确定。

梨园的 agent 要能扮演与修订正文，也要能制作和修改完整角色卡。用户此次进一步明确：**围绕角色卡编写复杂代码和交互产品、丰富体验，也属于这个独立能力维度**。现有 RP 工具验收不能代表卡创作能力完备。

用户实际用梨园写卡时，已经能创建角色卡和世界书；缺口是复杂卡中的代码、MVU 变量及其规则、各种状态栏等内容。后续需要把角色卡作为一个含相互依赖资源的完整作品调查，不能只补文本字段或增加“创建卡/创建世界书”按钮。

本维度覆盖：

- 卡内代码及关联资源的读取、定位和修改，保持原始结构与作者内容。
- MVU 变量结构、初值、更新规则与运行时结果之间的关系。
- 状态栏及其 HTML/CSS/JavaScript、模板和数据绑定。
- 围绕角色卡创建或修改可运行的交互组件、脚本及配套作品，覆盖资源组织、代码编辑和实际运行效果。
- 跨资源修改的一致性、预览和验证，以及导入导出的完整性。

## 调查结论与取舍

调查版本：[ai4rpg/tavern-cards](https://github.com/ai4rpg/tavern-cards/tree/f2b0238e2d5d4990adabb893a76c388bbb7cba46)；墨月为用户提供的本地工坊目录。完整调查与实验产物留在本机临时目录 `liyuan-card-authoring-20260908`，本节保存接手所需结论。

| 对象 | 值得采用的思路 | 已验证的限制 |
|---|---|---|
| tavern-cards | 资源清单、原文定位、确定性打包与补丁、MVU 修改的关联检查 | 测试卡往返会丢部分未知字段并重编号；同名世界书条目有覆盖风险；校验 schema 依赖可获得的源码 |
| 墨月本地写卡工坊 | 创作资料按需读取、源码与构建物分开、类型声明和宿主接口资料、可继续维护的工程 | 用户给出的目录是本地工程包；示例依赖酒馆及远程模块；check-card 的文件/引用检查不等于完整运行验收 |
| 梨园原有机制 | 原生 pi 助手、真实文件工具、卡空间、MVU 状态、消息帧与 ScriptHost | 完整资源原文缺入口；公开导出重建世界书丢元数据；脚本按长度判断更新会漏掉等长改码 |

当前结论是扩展**主会话的写卡模式与卡工程**。用户否定把独立助手作为主入口：主 agent 应能自行切换，在写卡时看到完整操作记录并取得代码工具，回到扮演后重新封闭这些内容。参考资料按任务选择，构建、资源映射和回写由确定性代码负责。没有复制第三方实现，也没有引入它们的强制创作流程、作者措辞检查或额外模型循环。两者的再分发条件仍需单独确认，未随梨园打包分发。

原包保留未知数据，编辑资源按原始 JSON 位置取得独立身份，不能以标题或内容去重来代表作品资源。卡内只有编译物或远程 import 时，不能声称已恢复原始 TypeScript/Vue 工程。

## 已实现切片与能力缺口

| 切片 | 用户结果 | 当前状态 |
|---|---|---|
| 1 | 看见已有卡的代码资源，改状态栏交互，预览、应用、撤回、导出再导入 | **已实现并验证**；入口在角色卡详情「代码与资源」，写卡模式使用共享 `card_project` 与原生文件工具 |
| 主会话模式 | 共用一份记录，写卡时开放操作内容，实时修改后回到原剧情 | **已实现并验证**；手动/模型自主切换、维护与剧情隔离、停止/恢复/排队；官方 DeepSeek 已通过基础修改及续演 |
| 2 | 从想法做出完整可玩卡，能够继续维护关联资源 | 尚未覆盖：按需创作资料、新增资源及元数据编辑、MVU schema/初值/规则/开场/界面的关联验证、源码构建与冲突同步；按实际需求选择范围 |
| 3 | 开发更复杂的页面交互作品 | 尚未覆盖：准确的宿主接口类型与模板、依赖和素材携带、生命周期与事件验收；按实际需求选择范围 |
| 后续 | 扩展酒馆生态兼容 | 按实际作品补 EJS、逐消息变量与更多 TavernHelper 语义，分别验收，不以能保存文本代表能运行 |

第一切片的「检查」是资源组装及已修改 JavaScript/正则的语法检查，**不是**完整 MVU/Zod 校验、TypeScript/Vue 编译或任意酒馆卡兼容。预览使用测试变量；剧情事实仍归 agent 与场记，搜索、折叠等状态归组件。卡档案 `AGENTS.md` 的演出语义保持独立，没有自动反向打入标准 PNG/JSON。

下一步从用户实际体验中的问题开始，复现完整操作链并确定修改归属；上表的后续切片作为能力缺口保留，不自动开始整批扩展。预设处理继续低优先级后置，不作为写卡前置条件。验收分别回答：能否打包、能否在目标宿主运行、是否达到创作体验；不能用任一项替代全部。
